# Universal creator/project discovery and update continuity

Requested 2026-11-16. Discover verified author identities, their projects/work and their public posting sources/communities; organize release, access and activity knowledge so adding or updating one project improves knowledge of the creator's other work. This is an additive goal for all database consumers, not a claim that the existing catalog covers the entire Internet or all of an author's work.

## Target record model and acceptance backlog

The following describes required future native records; it is not an implemented SQLite migration.

- [ ] Creator: stable provider-scoped ID, reviewed aliases/account links, role, evidence URL/authority, observation time, lifecycle and verification state. Similar names or avatars are discovery candidates only. Preserve collective/team roles and multiple authors instead of assigning sole authorship.
- [ ] Creator–project membership: project ID, author/contributor/publisher role, explicit evidence, time, confidence and discovery coverage. Discover all available work, but label the actual sites, pages and date range searched, failures, truncation and unknown coverage. Never label a partial scan “all projects.”
- [ ] Posting sources/communities: canonical public account/project/release/feed URL, source type, identity linkage evidence, last attempted/successful check, source-policy revision and rate/resource budget. Public sources do not grant access to private communities or credentials.
- [ ] Downloads: provider, project/release identity, metric definition, count, measurement time, covered interval, endpoint/source and scope. Store cumulative totals separately from interval counts, unique downloads, file downloads and user counts. Display site-specific totals with coverage/date; combine only proven compatible, nonoverlapping metrics. Unknown or unavailable counts remain unknown, not zero. Cross-site downloads are not unique users.
- [ ] Activity: attributable published/released/updated/last-seen timestamps, source and meaning. A recent scraper observation is not recent creator activity; no posts is not proof of abandonment.
- [ ] Release: provider release ID/version, platform/game/build/loader constraints, dependencies and incompatibilities, changelog source, license/source and dated access/price/currency/recurrence details. Unknown compatibility, license or access terms must remain unknown. Public availability is not a reuse license.
- [ ] Movement: old/new source, verified identity and per-project mapping, dated source status and evidence. Use the separately reviewed author-continuity contract; absence alone is not a ban. Retain provenance, corrections and historical source identities.

## Refresh behavior and bounded reference implementation

`tools/creator_refresh.py` implements a deterministic, read-only plan for `added` or `updated` project events. It selects reviewed creator memberships, checks other known projects by those creators and one outgoing hop of reviewed dependency/compatibility links. It caps each project-check batch, returns deferred IDs explicitly, and never performs an install, update, network call or persistent follow. Missing/unverified identities do not expand the graph. Its `verified` flags are reviewed input, not proof generated by this helper.

- [x] Tested reference refresh plan: add/update events, identity gates, related-project checks, deterministic bounds/overflow and no installation.
- [ ] Source adapters must retain evidence and establish graph edges under current source/publication policy before feeding this plan. Identity refresh itself needs bounded queues/pagination in the native scheduler.
- [ ] Persist event receipts, deduplicate/coalesce events, cache conditional responses, prioritize fresh changes, schedule overflow with retry/backoff and retain last-good records. No infinite recursive crawl or parallel fan-out by default.
- [ ] Reconcile creator/profile discovery and related-project release metadata into native storage; stale or retracted evidence must not silently reauthorize expansion.
- [ ] Consumer views: creator catalog, source coverage, site-specific downloads, activity timeline, release/dependency/compatibility context, access/price/license/changelog and movement notices.
- [ ] Integrate pre-update crash/freeze/bug advisories as information only. Users choose whether to update; refreshing related projects must never silently install or update them.
- [ ] Benchmark at realistic creator/catalog sizes using the [scale roadmap](catalog-scale-roadmap.md), with retained provenance and correctness baselines.

Current helper consumes an in-memory reviewed graph. It does not discover real accounts, scrape communities, provide a database service or prove production-scale performance. No factual creator/catalog/count claim is introduced by its synthetic tests.
